# conywhook forum: статический сайт

Форум, который хостится на **GitHub Pages** или **Netlify** (это статические хостинги).
Вся логика данных, входа и прав работает в **Supabase** (бесплатный Postgres с авторизацией).
Права проверяются в самой базе, поэтому их нельзя обойти из браузера.

Что умеет: разделы, треды, ответы, UID, роли (владелец / админ / участник),
регистрация только по инвайтам, модерация (закрепить, закрыть, удалить).

## Шаг 1. Создайте проект Supabase

1. Зайдите на https://supabase.com, создайте аккаунт и новый проект (бесплатный план подходит).
2. Дождитесь окончания инициализации проекта.

## Шаг 2. Настройте базу

1. **Перед запуском** откройте `supabase/schema.sql` и замените стартовый инвайт
   `CW-OWNR-0000-0001` на свой случайный код формата `CW-XXXX-XXXX-XXXX`.
   Он нужен, чтобы создать первого владельца, и после первой регистрации сгорает.
2. В Supabase откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql`
   целиком и нажмите **Run**. Выполнять нужно один раз.

## Шаг 3. Отключите подтверждение email

Логин в форуме сделан по нику и паролю. Email внутри используется служебно
(`ник@conywhook.local`), поэтому подтверждение почты нужно выключить:

**Authentication → Sign In / Providers → Email → выключите «Confirm email» → Save.**

## Шаг 4. Пропишите ключи

Откройте **Project Settings → API** и скопируйте:
- **Project URL** → в `SUPABASE_URL` в `js/config.js`
- **anon public key** → в `SUPABASE_ANON_KEY` в `js/config.js`

Anon-ключ публичный и безопасен в браузере. **Никогда не вставляйте `service_role` ключ** в
файлы сайта: он обходит все правила безопасности.

## Шаг 5. Создайте владельца

1. Запустите сайт локально: `python3 -m http.server 8000` в папке проекта и откройте
   http://localhost:8000
2. Откройте `#/register?invite=ВАШ-СТАРТОВЫЙ-КОД` и зарегистрируйтесь.
3. В SQL Editor выполните (подставьте свой ник):
   ```sql
   update public.profiles set role = 'owner' where lower(username) = lower('ВашНик');
   ```
4. Обновите страницу: появится пункт «Администрация».

Дальше владелец выдаёт админов в панели «Администрация», а владелец и админы создают инвайты для новых участников.

## Шаг 6. Выложите сайт

### Netlify (проще всего)
- Зайдите на https://app.netlify.com/drop и перетащите папку проекта.
- Либо подключите GitHub-репозиторий: Build command пустой, Publish directory — `.`

### GitHub Pages
1. Создайте репозиторий и загрузите в него содержимое папки (файлы должны лежать в корне репозитория).
2. **Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)`.**
3. Сайт появится по адресу `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПО/`.

После выкладки в Supabase: **Authentication → URL Configuration → Site URL** укажите адрес сайта
(для текущих функций это необязательно, но так правильнее).

## Структура

```
index.html            точка входа (одна страница, маршруты через #)
css/style.css         тёмная тема в стиле gamesense
js/config.js          адрес и публичный ключ Supabase
js/app.js             интерфейс, маршруты, формы, работа с Supabase
supabase/schema.sql   таблицы, регистрация по инвайту, права, функции
.nojekyll             отключает обработку Jekyll на GitHub Pages
```

## Безопасность

- Все изменения данных идут через серверные функции (`create_thread`, `mod_thread`, `set_role` и др.).
  Прямая запись в таблицы для браузера закрыта.
- Каждая функция проверяет роль того, кто её вызывает. Например, `set_role` работает только для владельца.
- Регистрация проверяет инвайт прямо в базе (триггер), поэтому обойти её через API нельзя.
- Пароли хранит Supabase Auth (хеширование на их стороне).
- Внутренние поля (auth UUID) не отдаются браузеру.
- Встроенные ограничения Supabase защищают вход и регистрацию от перебора.

## Ограничения

- **Нет самостоятельного восстановления пароля**: email служебный и недоступен пользователю.
  Если пользователь забыл пароль, разбираться с этим придётся вручную через панель Supabase (**Authentication → Users**).
- **Free-план Supabase** приостанавливает проект после недели без активности. Просто откройте его в панели, чтобы возобновить.
- **Нет пагинации**: все треды и сообщения выводятся на одной странице. Для форума с тысячами сообщений
  понадобится постраничный вывод.
- **UID могут иметь пропуски** после неудачных регистраций (так работает последовательность PostgreSQL).
- Старый Flask-проект (`conywhook-forum`) на статические хостинги не загрузить: ему нужен работающий Python-сервер.
  Этот сайт — его замена для Netlify и GitHub Pages.
